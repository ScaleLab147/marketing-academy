# 클라우드로 옮기기: 어느 기기에서든, 모든 직원이 같은 데이터로 일하기

로컬(내 컴퓨터)에 있는 데이터는 그 컴퓨터에서만 보입니다. 휴대폰·사무실 맥·노트북 어디서든, 모든 직원이 같은 코드와 같은 대화를 보려면 데이터가 클라우드(서버)에 있어야 합니다. 이 문서는 기기마다 흩어진 로컬 데이터를 한 번 옮기는 방법과, 앞으로 클라우드에서 일하는 방법을 정리합니다.

## 지금 어디에 무엇이 있나 (2026-09-27 점검)

| 데이터 | 위치 | 어디서든 보이나 |
| --- | --- | --- |
| 웹사이트 코드 | GitHub `ScaleLab147/marketing-academy` (공개 저장소) | 예 |
| 운영 중인 사이트 | Vercel. `main`에 합쳐도 자동으로 배포되지 않고, 마지막 배포(2026-04-30)도 직접 한 것 | 예 |
| 회원 로그인·가입 | Supabase | 예 |
| Claude 클라우드 대화: claude.ai/code, 휴대폰 Claude 앱의 Code 탭, 데스크톱 앱에서 Cloud로 시작한 대화 | Anthropic 서버 | 예, 같은 계정이면 모든 기기 |
| Claude 로컬 대화: 터미널 `claude`, 데스크톱 앱에서 Local로 시작한 대화 | 각 컴퓨터의 `~/.claude/projects` | 아니요, 그 기기에만 |
| 커밋하거나 GitHub에 올리지 않은 코드 | 각 컴퓨터의 프로젝트 폴더 | 아니요 |
| 비밀키 `.env.local` (Supabase·토스 키) | 각 컴퓨터 | 아니요. GitHub에 올리면 안 됨 |
| 강의 자료·이미지·영상 같은 파일 | 각 컴퓨터 | 아니요 |

터미널에서 한 로컬 대화는 기본 설정상 마지막으로 쓴 지 30일이 지나면 자동으로 지워집니다(데스크톱 앱 대화는 남아 있음). 옮길 대화가 있다면 서두르세요.

## 기기마다 한 번씩: 옮기는 순서

각 컴퓨터에서 한 번씩 합니다. 터미널이 낯설다면, 그 컴퓨터에서 Claude(데스크톱 앱 Local 또는 터미널 `claude`)를 프로젝트 폴더에서 열고 "GitHub main의 docs/cloud-migration.md 대로 이 기기 데이터를 클라우드로 옮겨 줘"라고 요청해도 됩니다.

### 1. 점검: 아무것도 바꾸지 않습니다

```bash
cd ~/marketing-academy   # 프로젝트 폴더. 기기마다 위치가 다를 수 있습니다
git fetch origin
git show origin/main:scripts/cloud-migrate.mjs | node --input-type=module -
```

GitHub에서 도구를 바로 받아 실행하는 방식이라, 이 기기에 남은 작업과 충돌하지 않습니다. 이미 `main`을 받아 두었다면 `node scripts/cloud-migrate.mjs`로 실행해도 똑같습니다. 프로젝트 폴더가 없는 기기(대화만 있는 기기)는 먼저 `git clone https://github.com/ScaleLab147/marketing-academy.git`으로 받은 뒤 그 폴더에서 실행하세요.

점검 결과는 세 부분으로 나옵니다.

- ① 코드: 커밋하지 않은 변경, GitHub에 없는 커밋과 브랜치, 임시 보관(stash)
- ② 비밀키 파일: `.env` 파일과 그 안의 변수 이름. 값은 보여 주지 않습니다
- ③ Claude 대화 기록: 프로젝트별 대화 수와 최근 제목

### 2. 코드 올리기

1번 명령 끝에 `--upload`를 붙여 다시 실행합니다.

```bash
git show origin/main:scripts/cloud-migrate.mjs | node --input-type=module - --upload
```

- GitHub에 없는 작업을 `backup/<기기이름>/<날짜-시각>/` 아래 브랜치로 올립니다. `main`은 건드리지 않습니다.
- 지금 작업 폴더, 스테이징, stash는 그대로 둡니다.
- 비밀키로 보이는 파일(`.env`, `*.pem`, `*service-account*.json` 등)과 50MB가 넘는 파일, 안쪽의 다른 git 저장소는 올리지 않고 목록으로 알려 줍니다.
- 같은 상태를 두 번 올리지 않습니다. 올린 뒤 다시 점검하면 "모두 GitHub에 올라가 있습니다"가 나옵니다.
- 기기 이름은 기본으로 컴퓨터 이름을 씁니다. 알아보기 쉽게 `--device office-mac`처럼 영문으로 정해도 되고, 같은 기기에서는 같은 이름을 계속 쓰세요.

> **주의: 저장소가 공개(public)입니다.** 올린 파일은 누구나 볼 수 있습니다. 1번의 목록을 확인하고, 올리면 안 되는 파일이 있으면 먼저 다른 곳으로 옮긴 뒤 실행하세요.

### 3. Claude 대화 옮기기

**기록으로 남길 대화 (전부)**: `--export-chats`를 붙여 실행합니다.

```bash
git show origin/main:scripts/cloud-migrate.mjs | node --input-type=module - --export-chats
```

바탕화면의 `claude-chats-<기기이름>` 폴더에 대화마다 Markdown 파일이 생깁니다. 사람이 보낸 요청과 Claude의 답만 담고, 도구 실행 결과는 뺍니다. 키처럼 보이는 값은 `[가림]`으로 바꾸지만 완벽하지 않으니 공유하기 전에 한 번 훑어보세요. Notion의 가져오기(Import) > Text & Markdown에서 이 파일들을 공유 페이지 아래로 가져오면 모든 직원이 어디서든 읽을 수 있습니다.

**계속 이어서 작업할 대화**: Claude 데스크톱 앱에서 그 대화를 열고, 세션 툴바 오른쪽 아래 VS Code 아이콘의 **Continue in > Claude Code on the Web**을 누릅니다. 데스크톱 앱이 브랜치를 올리고 대화 요약을 담은 새 클라우드 세션을 만들어 줍니다. 작업 폴더가 깨끗해야 하므로 2번을 먼저 하세요. 터미널에서 한 대화는 데스크톱 앱 입력창에 `/resume`을 입력해 먼저 불러옵니다.

### 4. 비밀키 옮기기

점검 결과 ②에 나온 변수의 값은 직접 옮깁니다. 채팅창에는 붙여넣지 마세요. 대화 기록에 그대로 남습니다.

- 운영 사이트: Vercel 프로젝트 > Settings > Environment Variables. 이미 들어 있으면 그대로 둡니다.
- 새 기기·새 직원: `.env.example`을 `.env.local`로 복사해 값을 채웁니다.
- Claude 클라우드 세션에서 실제 로그인·결제까지 돌려 봐야 할 때만: 클라우드 환경 설정(세션 제목 옆 환경 메뉴 > Edit)의 환경 변수에 넣습니다.

### 5. 그 밖의 파일

강의 영상·이미지·문서는 GitHub 말고 Google Drive 공유 드라이브나 Notion에 올립니다. 점검 결과에 50MB가 넘는 파일 목록이 나옵니다.

### 6. 마무리 (모든 기기를 마친 뒤 한 번)

클라우드 세션에서 "backup/ 브랜치들 검토해서 필요한 것만 main에 합쳐 줘"라고 요청합니다. 합친 뒤에는 backup 브랜치를 지워도 됩니다.

## 앞으로 일하는 방법

### 새 대화는 클라우드에서 시작합니다

| 기기 | 방법 |
| --- | --- |
| 휴대폰 | Claude 앱 > Code 탭 |
| 어느 브라우저든 | [claude.ai/code](https://claude.ai/code) |
| 맥 데스크톱 앱 | 첫 메시지를 보내기 전에 입력창의 환경 메뉴에서 **Cloud** 선택 (Local 아님) |
| 터미널 | `claude --cloud "할 일"`. 클라우드 대화를 터미널로 가져올 때는 `claude --teleport` |

클라우드 대화는 노트북을 닫아도 계속 돌아가고, 같은 계정이면 어느 기기에서든 이어서 볼 수 있습니다.

### 꼭 내 컴퓨터에서 해야 하는 작업

로컬 세션에서 `/remote-control`을 실행하거나 터미널에서 `claude remote-control`을 켜면, 휴대폰이나 브라우저에서 그 세션을 이어서 조작할 수 있습니다. 그 컴퓨터가 켜져 있어야 합니다.

### 사이트 배포도 클라우드에서

지금은 `main`에 합쳐도 사이트가 바뀌지 않아서, 누군가 자기 컴퓨터에서 직접 배포해야 합니다. Vercel 프로젝트 Settings > Git에서 GitHub 저장소 `ScaleLab147/marketing-academy`를 연결하면 `main`에 합칠 때마다 자동으로 배포되어, 어느 기기에서 작업하든 사이트에 바로 반영됩니다. 연결한 뒤에는 `main`에 합치는 것이 곧 운영 사이트를 바꾸는 일이 되니, 합치기 전에 PR에서 한 번 확인하세요.

### 직원과 함께 쓰기

- **대화 공유**: Team 요금제에서는 세션 공개 범위를 **Team**으로 바꾸고 링크를 보내면 같은 조직 직원이 볼 수 있습니다. 링크를 열 때의 최신 상태가 보이고 실시간으로 바뀌지는 않습니다. Pro·Max 요금제에는 Private와 Public만 있습니다.
- **코드 권한**: 지금 저장소 권한은 소유자 계정 하나뿐입니다. 직원이 자기 클라우드 세션에서 코드를 올리려면 GitHub 저장소 Settings > Collaborators에서 직원 계정을 추가하세요.
- **비밀키**: 채팅에 붙여넣지 않습니다. Vercel과 클라우드 환경 설정에만 둡니다.
- **공개 저장소**: 코드 말고 업무 자료·고객 정보·대화 기록은 GitHub에 올리지 않습니다. 저장소를 비공개로 바꾸려면 GitHub Settings > General > Danger Zone > Change visibility에서 바꾸고, 바꾼 뒤 Vercel 배포가 정상인지 확인하세요.
